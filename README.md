# 裁判工作台 · 通用 LLM-as-Judge 批量评测工具

本地网页工具：上传提测文件 → 写裁判规则 → 上传参考资料 → 确认字段与评分规则 → 批量评判 → 下载增加结果列的文件。

**不要求固定列名，不内置固定评分维度。** 支持使用不同服务商的OpenAI兼容Chat Completions接口。第一版按一行一个用例工作，不自动运行被测Agent。

## 1. 最快启动（Windows）

安装 Python 3.11 或以上版本（安装时勾选 Add Python to PATH），双击同目录的 **start.bat**。

首次启动会在本文件夹创建独立环境、联网安装依赖，随后打开 `http://127.0.0.1:8501`。以后双击同一文件即可。
关闭命令窗口会停止服务。不要对外暴露端口，也不要多人共享这个无登录的本地工具。

Windows启动文件使用ASCII和CRLF换行，环境检查由 `launcher.py` 完成。请勿将 `.bat` 改为LF换行；可运行 `start.bat --check` 仅检查环境。浏览器会在服务就绪后打开。

如需手动启动：

```powershell
cd <本项目目录>
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

macOS/Linux：将上述Python路径改为 `.venv/bin/python`。

## 2. 先用演示模式，不填Key

侧栏默认打开“演示模式”。在①勾选“加载内置演示数据”，②点“理解规则并推荐字段”，③检查后“确认此方案”，④勾选保存说明并“创建并开始评测”。

**演示模式只验证流程，不理解真实规则、不产生质量分数、不生成通过结论。** 不可把它用于模型排名。

## 3. 真实评测怎么用

1. 侧栏关闭演示模式，填写API Base URL、模型ID和API Key，点击测试连接。
2. ①上传Excel/CSV/JSON/JSONL。Excel可选工作表与表头行。JSON可指定对象数组的顶层键；JSONL每行一个对象。
3. 可选上传多份知识库、规范、标准答案。每份选择：
   - 全局参考：短且每条必须遵守的资料。
   - 自动检索：长资料，用当前问题查找相关段落。
   - 按字段匹配：表格型资料，按产品ID/知识ID精确对应。
4. ②粘贴或上传裁判规则。说明评测对象、评分档位、禁止行为、重大错误和通过条件；允许没有数值分数或没有通过标准。
5. 允许发送字段样例后，系统调用模型生成“评测方案”。导入旧方案时，可仅重新推荐字段映射而保留业务规则。
6. ③检查字段和维度。`c1/c2`是列位置ID，同名列也能区分。置信提示是模型自报，不是准确率保证。可手工改来源、选多个列或固定文本，也可在完整JSON中修改评分规则。
7. 保存方案JSON，下次复用。确认方案后，④选择数据范围、结果插入列、检索输入列、并发和版本后缀，开始评测。
8. 在记录区查看结果、证据、引用来源；生成结果文件并下载。原文件不会被改写。

**如果规则没有定义通过条件，就应保留 `overall_pass=null`；不要为了做统计擅自添加及格线。**

### 修改生成的方案

- **自然语言修改**：在③“用自然语言修改方案”填写要求（例如“删除忠实性维度，将工具结果映射到c24”），勾选发送授权后生成建议。先检查候选方案，再点击“应用修改后的方案”；也可放弃建议。演示模式不执行语义修改，真实模式会调用你配置的模型并可能计费。原始规则保留用于溯源，最新修改要求同时传给正式裁判。
- **字段增删与描述**：在③“调整字段对应”可以修改描述、来源、对应列和必需标记；勾选“删除此字段”后应用。新字段使用唯一英文标识，添加后再配置来源。这些操作只改评测方案，不改上传文件的列。删除被规则引用的字段时，必须明确确认是否同时删除关联规则。
- **引用错误修复**：如提示“规则vlm_use_enum引用了不存在的概念”，在“修复规则引用后应用方案”重新绑定已有字段，或明确删除该规则；也可以先补建缺少的字段。修复后应用即可继续确认。不会提供绕过无效规则直接运行的入口。
- 所有修改应用后均需重新“确认此方案”才能运行；候选方案生成后若底稿已改变，需重新生成建议，防止覆盖后续修改。

如果方案生成失败，页面会按每次尝试分别说明是输出截断、JSON语法错误、结构字段不合规、HTTP错误还是具体网络阶段失败，并展示模型原始返回；可下载完整诊断JSON。诊断只保留在当前页面会话中，不写入任务结果或本地日志。原始返回可能复述裁判规则或字段样例，下载后应按原始数据的敏感级别保管。

## 4. API兼容性

支持 `POST <base_url>/chat/completions`，也可填完整endpoint；只支持Bearer认证的兼容接口，不是任意厂商所有API。

- `json_schema`：请求模型遵守动态结构；服务商须支持该能力。
- `json_object`：请求返回JSON，本地仍做完整结构校验。
- `plain`：只靠提示要求JSON，本地仍校验。
- 不支持的模式返回错误，不会悄悄换模型或降级。
- 某些服务仅支持 `max_tokens`，可在高级配置切换参数名。
- 某些模型不接受Temperature，可取消发送。
- 价格自行填写，单位为同一种币种/百万Token；不填则费用显示未知，不冒充免费。
- 真实API会收费。模型可能误判，应先用人工已标注的小样本验证一致性，再扩大规模。

“测试连接”是独立的轻量请求：最大输出512 Token、连接阶段上限5秒、单次读取上限15秒、总等待上限20秒、不自动重试。界面显示发送、服务响应、格式检查和总耗时，区分网络超时、权限、限流、模型截断和格式不兼容；不读取提测文件/知识库，不修改正式评测设置。推理模型的512 Token预算通常足以产生可见JSON；如果仍被截断，则显示“模型已有响应但格式未验证”，不会误报网络连接失败。中止本机请求不保证服务商取消远端推理或计费。

输出上限也可能包含不可见推理Token，不能仅按预期JSON的字数判断是否足够，见[OpenAI Chat Completions参数说明](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

接口实现参考 [OpenAI结构化输出官方说明](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)。兼容服务实际支持范围以该服务为准。

## 5. 参考资料边界

支持文字PDF、Word、TXT、Markdown、Excel、CSV、JSON对象数组和JSONL；不支持扫描PDF/OCR、图片、音视频。单文件限30MB，压缩型文档解压上限150MB。

中文双字词与英文词BM25本地检索，无需Embedding Key。检索不是事实验证保证：没有命中不代表知识不存在。必需资料无命中、字段匹配失败、全局资料超过预算时，转为证据不足，不能强行判通过。

检索输入建议只选用户问题与必要上下文，不选被测模型的回答，以免幻觉引导检索。片段保留文件、页/段落/表格行位置。可在每条运行详情查看实际发送的原文。

## 6. 暂停、停止和断点恢复

每条完成即写入本地SQLite记录。暂停只停止派发新请求，已经发出的请求仍可能收费并会保存结果。停止同理，无法撤销服务商正在执行的请求。

关闭后重新启动，在④运行记录中选批次，再输入API Key，点击恢复。使用原批次的模型、规则、数据和资料，只更换Key，不会把不同配置结果混在同一批。

恢复可选择：仅未完成、未完成及请求失败、未完成及需复核。**如果进程在服务商已收费但本地尚未保存的瞬间退出，无法保证该条不重复计费**；其他已保存条目不会重复调用。

## 7. 结果与导出

输出公共列 `judge_status/model/rule_name/rule_version/time/overall_pass/reason/evidence/error_type/needs_review/reference_sources/raw_json/input_tokens/output_tokens/cost/judgeable/critical_error`，再加 `judge_<业务维度名>`。

状态包括：completed、mock、insufficient_evidence、input_too_long、api_error、format_error、refused、cancelled、internal_error。不能把API失败计作模型回答不通过；报告时应分别统计判定覆盖率与质量结果。

- 普通表格：结果可放在指定被评列右侧，右边的原列依次后移。
- **含公式、合并区域、命名范围、表格/筛选/条件格式/数据验证或图表等复杂对象的Excel，中间插列会被阻止，需改到最右列后导出，避免引用静默损坏。** openpyxl不能保证保留所有Excel扩展对象或签名；复杂工作簿请保留原件并抽查。
- 不计算公式；公式输出不要直接作为裁判证据，建议上传已粘贴成值的提测副本。
- 不改动其他表的单元格内容。完整Excel保留其余工作表；异常用例另导出CSV。
- JSON保留原记录嵌套值，附加结果字段；JSONL保留一行一个对象。
- 原文件已有结果时可跳过已有行、显式覆盖judge_列，或加新版本后缀。禁止覆盖非judge_原列。
- Excel单元格最多32767字符，超长结果会标注截断；完整详情保留在本地运行记录/JSON日志。

## 8. 数据和Key安全

Key只在进程内存里，且模型回显中的本次Key会脱敏。不会写入方案、元信息、日志或结果。完整证据保存在本地 `data/jobs/<运行编号>/`，包括原文件、方案、解析后的资料、请求、响应。

**“本地工具”不表示输入永远不出网**：真实模式的字段分析和逐条裁判会把选定内容发往填写的API。请先确认公司资料可以发给该服务商。Key不要写在裁判规则或上传资料里，也不要把整个data目录发给其他人。

不执行文件脚本/宏，不通过模型生成代码执行规则。自动规则只支持有限数据检查（nonempty/equals/one_of/contains/json_valid），复杂语义由LLM判。防提示注入是分层提示和证据隔离，不保证模型绝不受攻击；重要判定仍需人工抽查。

删除旧运行记录：先停止对应任务，再删除其 `data/jobs/<运行编号>` 文件夹（含敏感原始文件）；该工具没有云端备份或垃圾箱。

自动测试涵盖：异构表头、动态评分结构、资料检索/匹配、无证据保护、Excel插列保真/公式保护、JSON往返、注入防护、HTTP重试和用量、规则冲突、断点恢复、Key脱敏以及Streamlit界面流程。

## 10. 常见问题

| 情况 | 处理 |
|---|---|
| HTTP401/403 | 检查Key、权限和API提供方是否对应 |
| HTTP400 | 检查模型、结构化模式、Temperature与输出Token参数 |
| HTTP429 | 降低并发/每分钟请求；系统自动有限重试 |
| 证据不足 | 在详情看缺少字段或资料命中情况，补资料后新建批次 |
| 结构错误 | 提高输出Token上限，使用JSON模式，检查维度定义 |
| 导出列重名 | 更换后缀，或明确选择覆盖已有judge_列 |
| 中间插列被阻止 | 将导出位置选为最右列，保护原引用 |
| 启动时端口被占用 | 关闭另一个工作台，或手动指定另一个端口 |
| 全局资料太长 | 缩短必读规则，长知识库改为检索模式 |
| 模型误判 | 不等于工具故障；调整明确的规则并人工校准，版本化重跑 |
